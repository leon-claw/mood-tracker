# AI 助手对话入口与日志历史迁移设计

## 目标

将底部导航中的“日志”入口改造成 AI 助手对话入口，同时把原有日志历史页面迁移到“我的/设置”中。第一阶段只实现本地 UI 框架和本地占位交互，不调用 AI 模型、网络 API，也不持久化对话内容，为后续接入 AI agent 保留清晰边界。

## 已确认范围

- 底部导航继续保留四个位置：AI、趋势、日历、我的。
- 中间“+”按钮继续负责新增每日记录，不改动现有记录流程。
- 原日志历史页面的搜索、心情筛选、查看记录和删除记录能力全部保留。
- “日志历史”作为“我的”页面中的设置入口，进入独立页面。
- 新增独立 `AssistantPage`，负责 AI 对话页面的展示和 UI 状态。
- 本轮不接入 `@google/genai`，不读取 API Key，不发送网络请求。
- 本轮不新增数据持久化结构；刷新页面后对话内容可以清空。

## 用户流程

### 进入 AI 助手

用户点击底部导航的“AI”后，进入 AI 对话页面。页面显示欢迎消息、简短说明和快捷问题。用户可以在输入框中输入内容并发送，页面追加一条本地用户气泡以及一条明确标记为“AI 功能接入后会在这里回复”的占位消息。

### 进入日志历史

用户进入“我的”，点击“日志历史”设置项，进入原日志历史页面。页面保留原有标题、记录数量、搜索输入框、心情筛选、记录时间线和删除确认流程。返回按钮回到“我的”页面。

## 路由设计

应用标签类型从语义上区分 AI 页面和日志历史页面：

- `assistant`：`#/assistant`，底部导航的 AI 页面。
- `report`：`#/report`，趋势页面。
- `calendar`：`#/calendar`，日历页面。
- `profile`：`#/profile`，我的页面。

日志历史使用个人设置子路由：

- `#/profile/log-history`：日志历史页面。
- `#/profile/record-fields`：记录模块设置，保持不变。
- `#/profile/reminders`：提醒设置，保持不变。

为兼容已经保存的旧链接，`#/log` 映射到 `assistant`，不再直接打开日志历史。未知路径继续回到趋势页面。日志历史子路由只在 `profile` 标签下渲染，并且打开时隐藏底部导航，与现有设置子页面行为一致。

## 组件边界

### `AssistantPage`

新增 `src/components/AssistantPage.tsx`，只负责 AI 对话页面的 UI 和本地临时消息状态。组件接收返回回调，不直接访问 `App` 的记录数据、localStorage 或 AI SDK。组件内部包含：

- 页面头部：AI 图标、标题“AI 助手”和简短副标题。
- 消息区域：欢迎消息、快捷问题、本地发送消息和占位回复。
- 输入区域：多行输入框、发送按钮和未接入状态提示。

### `LogHistoryPage`

新增 `src/components/LogHistoryPage.tsx`，从 `App.tsx` 中提取现有日志历史页面的展示结构。组件接收：

- `entries`：当前本地记录列表。
- `searchQuery` 和 `onSearchQueryChange`：搜索状态。
- `selectedMoodFilter` 和 `onMoodFilterChange`：心情筛选状态。
- `onDelete`：请求删除记录的回调。
- `onBack`：返回“我的”页面的回调。

删除确认、记录编辑和数据计算仍由 `App` 负责，避免在迁移页面时改变现有业务逻辑。

### `App.tsx`

`App` 负责：

- 根据路由渲染 `AssistantPage`、趋势、日历或我的页面。
- 维护日志历史子页面的打开状态和路由同步。
- 将日志历史入口加入“我的/设置”列表。
- 保留现有记录弹窗、删除确认、自动数据同步和本地存储流程。

## AI 对话页面视觉设计

页面遵循 Mood Tracker 的自然疗愈移动端规范：

- 使用 `bg-[#F9F8F6]` 作为页面基底，避免大面积深色或渐变。
- 页面头部使用白色圆角卡片、低对比度边框和柔和阴影。
- AI 气泡使用浅 sage 背景，如 `#E6F0E6`，左侧配 `Sparkles` 或 `MessageCircle` 图标。
- 用户气泡使用主 sage 色 `#8FA88B`，文字为白色，靠右显示。
- 快捷问题使用白色或 `gray-50` 的圆角胶囊按钮，边框保持低对比度。
- 输入框使用 `bg-gray-50`、柔和边框和 `rounded-2xl`，聚焦时使用 sage 边框。
- 发送按钮使用现有主操作样式：sage 圆形按钮、白色图标、轻微阴影和按下缩放。
- 数值和状态提示使用项目现有的 `font-mono` 或小号辅助文字；不使用企业后台式表格或厚重工具栏。
- 页面底部为输入区域预留足够空间，不能被底部导航遮挡。

页面空状态文案保持简短、诚实，例如“先从今天的状态开始聊聊”和“AI 功能接入后会在这里回复”。不展示已经接入模型或已分析数据的虚假状态。

## 本地交互

- 输入为空时，发送按钮不可用。
- 发送有效内容后，消息区域追加用户消息。
- 随后追加一条本地占位回复，说明当前尚未连接 AI 服务。
- 点击快捷问题时，将问题填入输入框或直接按同样的本地发送流程处理，保持 UI 可演示但不产生网络请求。
- 对话状态只保存在组件内存中，页面刷新或离开后清空。

## 错误和兼容性

- 本轮没有网络调用，因此不新增网络错误或 API 错误状态。
- 路由解析必须兼容旧的 `#/log` 链接。
- 日志历史迁移不得改变已有记录筛选、排序、删除和打开编辑弹窗的行为。
- 设置子页面打开时继续隐藏底部导航，返回后恢复“我的”页面和底部导航。
- 桌面宽屏和 360px 左右的窄屏都要保持输入框、按钮和消息气泡不溢出。

## 测试与验收

- 更新路由测试：验证 `#/assistant`、旧 `#/log`、`#/profile/log-history` 和现有设置路由的解析结果。
- 新增 `AssistantPage` 渲染测试：验证标题、欢迎消息、输入框、快捷问题、发送按钮和未接入提示存在。
- 新增或更新日志历史页面测试：验证搜索、筛选和删除回调仍连接到页面。
- 更新底部导航文案测试：验证显示“AI”，不再显示“日志”。
- 更新“我的”页面测试：验证存在“日志历史”入口。
- 运行 `pnpm lint`、`pnpm build` 和现有测试脚本。
- 人工检查手机壳 420px 宽度及窄屏下的 AI 页面、输入区域和设置入口。

## 非目标

- 不在本轮接入 Gemini 或其他 AI 服务。
- 不在本轮设计 agent 工具调用、上下文编排、提示词模板或权限模型。
- 不改变记录数据结构、自动采集模块、本地存储格式或 Android 原生能力。
- 不删除日志数据，也不删除原有日志相关业务代码；只调整入口和页面组件边界。
